# Rules for adding to this repo

1. Only add an entry after you've actually run the command. Tag it `<!-- verified: YYYY-MM -->`.
2. Write the "Why it bites" section while the failure is still fresh — you will not remember the exact error message a week later.
3. Never write literal real-world data: project IDs, project numbers, service account emails, private IPs, Cloud Run URLs, bucket names, Cloud SQL instance/connection names, company domains, personal emails. Use `<PLACEHOLDER>` form, then one filled fake example (Nike / `nike.com` / `nike-retail-prod`) so the shape is still readable.
4. If unsure whether a string identifies a real person, company, or project — replace it.
